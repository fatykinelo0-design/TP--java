  Q1. Quand je tape java -version, je vois que la version installée est Temurin 25.0.4.1 (LTS). La commande java sert à lancer un programme Java, tandis que javac permet de le compiler. Pour utiliser javac, il faut avoir installé un JDK, car un simple JRE ne contient pas le compilateur.
 Q2. Après avoir compilé mon programme avec javac, je remarque qu'un fichier Bonjour.class est créé. Ce fichier ne ressemble pas à un fichier texte classique, car il contient du bytecode Java. C'est ce code que la JVM va ensuite exécuter.
 Q3. La différence avec Python, c'est qu'en Java, il faut d'abord compiler le programme avant de pouvoir le lancer. Cette étape permet de repérer certaines erreurs, comme les erreurs de syntaxe ou de types, avant l'exécution.
 Q4. J'obtiens une erreur parce que ma classe publique s'appelle Salut, alors que mon fichier ne porte pas le nom Salut.java. En Java, le nom d'une classe publique doit obligatoirement correspondre au nom du fichier.
  Q5. Oui, VS Code peut repérer certaines erreurs directement pendant que j'écris mon code Java, grâce à son extension Java. En Python, Pylance peut aussi m'aider à repérer des erreurs, comme une parenthèse oubliée. Par contre, certaines erreurs ne se manifestent qu'au moment où le programme est lancé.
  Q6. En Java, si j'essaie de mettre du texte dans une variable de type int, le compilateur refuse le programme, car les types ne correspondent pas. En Python, une annotation comme x: int = "texte" n'empêche pas le programme de s'exécuter, car Python ne vérifie pas automatiquement les annotations de type.
 Q7. Les fichiers .gitignore servent à éviter d'envoyer sur GitHub des fichiers inutiles. En Java, on peut ignorer target/, les fichiers .class et certains dossiers de configuration. En Python, on ignore plutôt __pycache__/ et .venv/, par exemple. Ces fichiers ou dossiers peuvent souvent être recréés, donc les enregistrer dans Git n'est pas toujours utile.
 Q8. Dans le fichier pom.xml, la partie dependency permet d'ajouter des bibliothèques dont mon projet a besoin. Ici, j'utilise Gson, avec le nom gson et la version 2.11.0. C'est un peu le même principe que lorsque j'installe une bibliothèque Python avec pip install.
 Q9. Maven conserve les bibliothèques téléchargées dans un dossier appelé .m2. L'avantage, c'est que si plusieurs projets utilisent Gson, Maven n'a généralement pas besoin de télécharger cette bibliothèque à chaque fois. Cela permet de gagner du temps et de l'espace.
 Q10. Dans Maven, le groupId, l'artifactId et la version permettent d'identifier précisément une bibliothèque ou un projet. En Python, on retrouve aussi des informations pour identifier les paquets, mais on n'utilise pas exactement le même système.
  Q11. Dans une méthode Java, public signifie qu'elle peut être utilisée depuis d'autres classes, tandis que static permet de l'appeler sans créer d'objet. Le type double indique que la méthode renvoie un nombre décimal. En Python, le fonctionnement est différent, car on n'utilise pas directement les mêmes mots-clés.
  Q12. Lorsque je donne une liste vide à ma méthode, j'obtiens une IllegalArgumentException, car j'ai prévu un test pour éviter ce problème. En Python, si je ne vérifie pas que la liste contient des éléments, le calcul d'une moyenne peut provoquer une erreur de division par zéro.
 Q13. En Java, lorsqu'on utilise un package comme fr.b1, l'organisation des dossiers doit correspondre à ce package. Par exemple, le fichier doit se trouver dans le dossier fr/b1/ à partir de la racine des sources. Python est plus souple sur ce point pour un simple script.
 Q14. Quand je désactive la dépendance Gson dans mon projet, la compilation échoue parce que Java ne trouve plus cette bibliothèque. En Python, si la bibliothèque requests n'est pas installée, j'obtiens généralement une erreur ModuleNotFoundError lorsque le programme essaie de l'importer.
 Q15. Lorsque j'utilise le JDK 21 pour compiler un projet prévu pour Java 25, j'obtiens l'erreur « release version 25 not supported ». Cela vient du fait que le JDK 21 ne prend pas en charge cette version de Java. Dans mon fichier pom.xml, le paramètre maven.compiler.release est réglé sur 25.
 Q16. La variable JAVA_HOME permet d'indiquer aux outils, comme Maven, où se trouve le JDK à utiliser. Si je modifie cette variable uniquement depuis mon terminal, le changement reste temporaire. Il disparaît généralement lorsque je ferme le terminal, contrairement à une modification enregistrée dans les variables d'environnement du système.
  Q17. Changer de version de Java peut prendre du temps, car il faut vérifier que tout fonctionne encore et refaire des tests. Donc, si un ancien projet fonctionne bien, on peut garder sa version LTS tant qu'elle est encore supportée.
 Q18. Pour créer un environnement virtuel en Python avec la version 3.12, je peux utiliser la commande py -3.12 -m venv .venv sous Windows. Je peux aussi utiliser un outil comme pyenv pour gérer plusieurs versions de Python. Chaque projet peut ainsi avoir son propre environnement adapté à ses besoins.
 Q19. Avec Java, je dois d'abord compiler mon programme avant de l'exécuter, ce qui permet de détecter certaines erreurs assez tôt. Python est plus direct à utiliser, car je peux lancer mon script sans étape de compilation classique. En revanche, Python peut être plus lent à l'exécution dans certains cas et certaines erreurs apparaissent seulement lorsque le code est exécuté.
  Q20. Java est compilé en bytecode, qui est ensuite exécuté par la JVM. Comme il existe des versions de la JVM adaptées aux différents systèmes, cela permet d'utiliser le même bytecode sur plusieurs plateformes. Il faut toutefois disposer d'un environnement Java compatible sur la machine qui exécute le programme.
 Q21. Le typage strict est particulièrement intéressant pour un gros projet de 50 000 lignes, car il devient difficile de repérer toutes les erreurs à la main. Le compilateur Java peut détecter certaines erreurs de type avant même que le programme soit lancé. Pour un petit script de 20 lignes, les erreurs sont souvent plus faciles à repérer et à corriger.
  Q22. Pour choisir un langage, tout dépend de ce que je veux créer. Pour renommer rapidement des fichiers, je choisirais Python, car il est simple et rapide à utiliser. Pour une application Android, je pourrais utiliser Java ou Kotlin. Pour analyser des données, Python est très pratique grâce à des bibliothèques comme Pandas et NumPy. Enfin, pour le serveur d'une banque, Java peut être un bon choix grâce à son typage strict, à ses performances et à son écosystème professionnel.
 Q23. Entre les deux TP, j'ai retrouvé plusieurs éléments communs : la configuration de Git et de SSH, l'utilisation de VS Code, le fichier .gitignore, le dépôt GitHub, le README et le fichier REPONSES.md. Cela montre que même si le langage change, les outils utilisés pour organiser et partager le travail restent souvent les mêmes.
